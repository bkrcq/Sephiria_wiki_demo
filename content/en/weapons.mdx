# Sephiria Weapons & Upgrade Paths

## Confirmed weapon scope

Launch coverage of the 1.0 release described six weapons with more than fifty unlockable upgrades each, which is consistent with the broader 200+ total. That press-reported detail is useful for one thing: it tells you each branch has real depth, so the choice of branch is a long-term commitment, not a cosmetic one. It does not tell you which branch is strongest, and this page does not claim otherwise.

## How to choose a weapon branch without a tier list

With six branches and no verified ranking, the right question is not "which branch is best?" but "which branch can I execute consistently for this run goal?" Use these four criteria, in this order:

1. **Range.** How close must you stand to deal damage? Short-range branches demand better positioning and punish mistakes faster. Long-range branches give you more time to react but may require more patience. Pick the range that matches your positioning habits, not the range a stranger recommended.
2. **Speed.** How fast does the branch attack and recover? A fast branch forgives mistimed inputs because the next action comes quickly. A slow branch punishes every missed read. If you are still learning a chapter, speed and recovery usually matter more than raw damage.
3. **Damage style.** Does the branch reward steady pressure, burst windows, or careful setup? Match the style to the run: steady pressure suits long chapters, burst windows suit short encounters, and setup-heavy styles suit runs where you control the pace.
4. **Synergy surface.** How does the branch interact with the artifacts, tablets, and animal synergies you tend to find? A branch is only as good as the combinations it enables in your hands. Record which combinations actually appeared in your runs instead of assuming them in advance.

Write down your answers before the run. After the run, check whether the branch behaved the way you expected. If it did not, your note should say what surprised you — that surprise is the most valuable part of the test.

## Planning an upgrade route

An upgrade route is a sequence of choices, not a shopping list. Because no verified node-by-node upgrade map exists, plan routes around principles instead of named nodes:

- **Fix the branch first.** Switching branches mid-run resets everything you learned about timing and range. Commit to one branch per run unless the run goal is explicitly to compare branches.
- **Spend on the bottleneck.** If your runs end because you take too much damage, upgrades that improve survival help more than upgrades that add damage. If your runs end because encounters drag on, damage upgrades help more. Name the bottleneck before spending.
- **Keep one upgrade unspent when you can.** Holding back one choice gives you flexibility when the next room or encounter reveals what the run actually needs. This is a habit, not a game mechanic — but it prevents the common error of spending everything early and then facing the real problem empty-handed.
- **Record the order.** Two runs with the same upgrades in a different order are different experiments. Write down the order you chose, so a later reader can reproduce the route.

## A testing protocol for comparing two branches

If you want to know whether Branch A or Branch B suits you better, do not alternate randomly between them. Run this protocol:

1. **Pick a fixed run goal** — for example, chapter progression in the same chapter, solo, same mode.
2. **Run Branch A three times** with the worksheet from the [Grimoire build page](/weapons/grimoire), changing nothing else you can control.
3. **Run Branch B three times** under the same conditions.
4. **Compare the notes, not the memories.** Look at what ended each run, which bottleneck appeared, and how consistent the results were.
5. **Keep the winner for one more session** before calling it your main branch. A branch that wins once may have won on luck.

This takes longer than copying a tier list, but it answers the question tier lists pretend to answer: what works for you, in the runs you actually play.

## Recording upgrades so the note stays useful

A weapon note is useful to a future reader only if it can be reproduced and checked. Include:

- The weapon branch, described in your own words by range, speed, and damage style.
- The upgrades taken, in the order taken, described by observed effect rather than by invented names or numbers.
- The artifacts, tablets, and animal synergies present during the run.
- The mode, party size, chapter, and game version.
- What ended the run, in one sentence.
- One change you would test next.

Do not include damage numbers, drop rates, rarity labels, or unlock requirements unless you can point to the in-game evidence or an official source that states them. Numbers without a source are the fastest way to turn a helpful page into a misleading one.

## Co-op and Hard Mode

Online co-op supports up to four players, and Hard Mode contains 60 levels. Exact party roles, weapon meta, unlock requirements, and scaling values are **unconfirmed**.

In co-op, weapon choice becomes a party decision. The developer's 1.0 announcement describes teammates trading items and reviving fallen companions, so a party can cover different ranges and roles instead of all choosing the same branch. Agree before the session on who covers close range, who keeps distance, and who prioritizes recovery. After the session, record the party composition alongside the individual results — a branch that looks weak alone may be the right pick when the party needs its range or speed.

In Hard Mode, treat weapon choice as an endurance decision. A branch that feels strong on the first floors can run out of recovery later. Record which floor each run reached and what ended it. Over several runs, a pattern will appear: the branch that survives longest is usually the one whose bottleneck you have learned to manage, not the one with the highest theoretical damage.

## Common mistakes

- **Shopping by name.** Without a verified catalogue, a weapon name found in a search result is not proof of a weapon's strength, or even of its exact role. Judge branches by observed range, speed, and damage style.
- **Upgrading everything evenly.** Spreading upgrades across every option usually means no option is strong enough when it matters. Concentrate on the branch you committed to.
- **Chasing damage when survival is the bottleneck.** More damage does not help if the run ends the same way for the same reason. Fix the actual cause of failure first.
- **Ignoring version context.** Balance patches can change upgrade behavior. A route recorded before a patch is a historical note, not a current recommendation, until it is retested.
- **Comparing runs with different goals.** A branch that shines in boss practice may look weak in Hard Mode. Compare only runs that shared a goal.
- **Trusting a ranking with no method.** A list that does not state its game version, test conditions, or run goal is not evidence. This site does not publish one.
