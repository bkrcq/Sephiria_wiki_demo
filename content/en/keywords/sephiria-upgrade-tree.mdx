## Sephiria upgrade tree: what is confirmed

The official Steam information for Sephiria describes **six weapon branches** — Sword and Shield, Dagger, Greatsword, Crossbow, Blade, and Staff — and **more than 200 upgrades**. As of **October 21, 2026**, the official sources checked for this page did not provide a complete node-by-node upgrade-tree map, node costs, prerequisites, or a universally best route; those details remain **unconfirmed**. However, the patch notes do document many individual upgrades by name, and those are collected in the next section.

Two structural facts also come from the notes: upgrades can be **removed and reworked**, not only added (the 0.9.6 Greatsword removals), and new branches arrive with their own upgrade sets (Staff in 0.11.0). Any tree map that ignores version history will mislead within one patch cycle.

Launch coverage of the 1.0 release described six weapons with more than fifty unlockable upgrades each, which is consistent with the broader 200+ total. That press-reported detail is a useful planning hint: each branch has enough depth that specializing in one branch is a real commitment. It is not a substitute for a verified node map, and this page does not present it as one.

## Why there is no node-by-node map on this page

A trustworthy upgrade-tree map is a demanding document. Every node would need:

- The weapon branch it belongs to.
- The node name exactly as shown in-game.
- The observed effect, described from gameplay rather than guessed from a name.
- The cost or requirement to unlock it.
- Its prerequisites, if any.
- The game version the observation was recorded on.
- A reproducible source: a screenshot, a clip, or an official reference.

The official sources reviewed for this page do not supply that level of detail. Publishing a map assembled from guesses, half-remembered runs, or other wikis' unverified claims would look complete while being wrong in ways a reader cannot detect. A transparent statement of the limits is more useful than a fabricated diagram.

## How to map your own upgrade tree from in-game evidence

You can build a reliable personal upgrade map without waiting for an official one. The method is slow, but every entry in it will be true:

1. **Pick one branch.** Map one branch at a time. Mapping all six at once guarantees confusion.
2. **Record nodes as you unlock them.** For each node, write the name exactly as shown in-game, the observed effect in one sentence, the cost or requirement, and the game version.
3. **Photograph or clip the evidence.** A screenshot of the node screen beats a memory written down an hour later. Keep the evidence with the note.
4. **Mark guesses as guesses.** If you think a node "probably" requires another node but have not verified it, write "unconfirmed" next to it. Future-you will thank present-you.
5. **Retest after patches.** Balance patches can change costs, effects, or prerequisites. When a patch lands, retest the nodes you rely on and update the version stamp on the note.

After a few runs, your personal map will cover the nodes you actually use. That is more valuable than a complete-looking map whose entries you cannot trust.

## A recording template for upgrade notes

Copy this template for each node you document:

- **Branch:** the weapon branch, in your own words by range, speed, and damage style.
- **Node name:** exactly as shown in-game.
- **Observed effect:** what the node did in gameplay, in one sentence.
- **Cost / requirement:** what it took to unlock, as observed.
- **Prerequisite:** the node or condition required first, or "unconfirmed."
- **Game version:** the version the observation was recorded on.
- **Evidence:** screenshot, clip, or official reference.
- **Status:** confirmed by observation, or unconfirmed.

A node note without a version stamp and evidence is a rumor, even if you wrote it yourself.

## How to plan an upgrade route without a full map

You do not need the full tree to plan sensibly. Use this sequence:

1. **Name the run goal.** Chapter progression, boss practice, co-op, Hard Mode, or learning — the goal decides what the route should optimize. See the [Grimoire build page](/weapons/grimoire) for the run-goal method.
2. **Commit to one branch.** Switching branches mid-run throws away everything the route was built on.
3. **Spend on the bottleneck.** If runs end because you take too much damage, prioritize survival. If runs end because encounters drag on, prioritize damage. Name the bottleneck before spending.
4. **Upgrade in an order you can repeat.** Write down the order you chose. Two runs with the same upgrades in different orders are different experiments.
5. **Change one thing per run.** If a route performs better after five simultaneous changes, you have learned nothing about which change helped.

This is the same discipline behind the build-testing method on the [weapons page](/weapons): one variable at a time, notes over memory, version stamps on everything.

## Prioritization: what to record first

If you are mapping the tree yourself, record in this order:

1. **The nodes you actually take.** Your own route matters more than a complete catalogue.
2. **The prerequisites of those nodes.** These decide whether a route is even possible.
3. **The costs of those nodes.** Costs decide the order a route must follow.
4. **The nodes that ended runs.** If a run ended because you could not reach a node in time, that node belongs at the top of your next plan.
5. **Everything else.** A complete map is a nice-to-have. A correct map of your own route is the need-to-have.

## Common mistakes

- **Treating the upgrade count as a shopping list.** "200+ upgrades" describes the size of the system, not a recommended path through it. A count is not a route.
- **Copying a route with no version stamp.** Routes recorded before a patch may not behave the same way after it. Check the version before trusting a route.
- **Assuming prerequisites from names.** A node that sounds like it should require another node may not. Verify prerequisites by observation, and mark them unconfirmed until you do.
- **Optimizing for damage when survival is the bottleneck.** More damage does not help if the run ends the same way for the same reason.
- **Filling gaps with other wikis' claims.** If a claim has no source you can check, it does not become true by appearing in two places. Keep it marked unconfirmed.
- **Mapping all six branches at once.** Depth on one branch beats a shallow, error-prone sketch of all six.
