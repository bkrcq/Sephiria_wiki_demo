## What "puzzle" can mean in a roguelite

Players use the word puzzle for several different things, and the confusion causes most bad puzzle advice. Before following any tip, identify which kind it is:

- **Environmental interaction.** Something in a room responds to an action: a switch, a pressure plate, a destructible wall, a sequence of interactables. These are testable in a single run.
- **Item-gated interaction.** Something responds only when you carry a particular artifact, tablet, or weapon. These need at least two runs to confirm: one with the item, one without.
- **Sequence or pattern.** Something requires inputs in a specific order. These need an exact input log, because one wrong step makes the whole attempt fail.
- **Hidden room or passage.** Something leads somewhere unmarked. These need a location description precise enough for another player to reproduce — chapter, room type, and landmarks.
- **Rumor.** Something someone said exists, with no reproducible evidence. Rumors are leads, not guides. Treat them as "unconfirmed until tested" and never as instructions.

A tip that does not say which kind it is, or that mixes kinds together, is not ready to follow.

## How to test a puzzle tip before trusting it

Community puzzle tips are worth testing, but test them like experiments:

1. **Write down the claim first.** What exactly should happen, where, and with what setup? If the tip cannot be stated precisely, it cannot be tested precisely.
2. **Record the setup.** Chapter, room, game version, weapon branch, artifacts, tablets, and party size. A tip that works only with a specific item is a different claim from a tip that works always.
3. **Try it exactly as stated.** Do not improvise on the first attempt. If it fails, the tip is wrong as stated — even if a modified version later works.
4. **Try it once more.** One success can be coincidence; one failure can be a misread. Two attempts with the same setup give you a first signal.
5. **Try the control case.** If the tip involves an item, try the same room without the item. If the result is the same, the item was not the cause.
6. **Write down the result.** Success, failure, or partial result, with the setup attached. A failed test is valuable evidence — it saves the next player a wasted run.

If a tip survives this process, it graduates from rumor to a documented observation. If it does not, say so plainly. Negative results are content, too.

## How to document a real puzzle solution

For a useful future guide, record the chapter or room, the trigger, every input in order, the game version, and a screenshot or video that shows the resulting reward. Cross-check it against the [official Steam update history](https://store.steampowered.com/news/app/2436940), because patches can change interactions.

Use this template for each documented puzzle:

- **Location:** chapter, room type, and landmarks another player can find.
- **Kind:** environmental, item-gated, sequence, hidden passage, or other — in one phrase.
- **Trigger:** the exact action that starts the interaction.
- **Inputs:** every input in order, with no skipped steps.
- **Setup required:** weapon branch, artifacts, tablets, party size — or "none observed."
- **Result:** what happened, described from observation, including the reward if any.
- **Game version:** the version the observation was recorded on.
- **Evidence:** screenshot or video showing the result.
- **Status:** confirmed by repeated observation, or single observation awaiting retest.

A solution note missing the location, the input order, or the version stamp cannot be reproduced, and a guide that cannot be reproduced is not a guide.

## How to explore without wasting runs

Puzzle hunting inside a roguelite competes with the rest of the run. Use these habits to keep exploration productive:

- **Give exploration its own runs.** A run dedicated to exploring one area teaches more than a run where you explore "when convenient" while chasing progression.
- **Explore one area per run.** Note which chapter or room type you are investigating, and leave the rest for later runs.
- **Check the edges.** In a tower-based game, walls, corners, and dead-end rooms are the natural places to look first — but "look first" is a suggestion, not a claim that anything is hidden there.
- **Revisit with different setups.** If a room seemed inert, try it again with a different item set on a later run. Item-gated interactions only reveal themselves this way.
- **Stop when the run goal changes.** If you came to progress and exploration is now eating the run, write down what you saw and come back with an exploration run. One goal per run keeps notes honest.

## Common mistakes

- **Following a solution with no version stamp.** Patches can change interactions. An undated solution is a guess about the current game.
- **Skipping steps.** A sequence puzzle with a skipped step is a different puzzle. If a guide's steps do not work, the guide is wrong as written — do not assume you misread it.
- **Confusing correlation with cause.** If a room behaved unusually while you carried a particular artifact, the artifact may or may not be the cause. Test without it before claiming a connection.
- **Trusting a reward claim without evidence.** Rewards are the most exaggerated part of puzzle rumors. Require a screenshot or clip showing the reward before treating it as confirmed.
- **Treating exploration systems as puzzles.** The confirmed systems — exploration, artifact collection, upgrades — explain why players hunt for hidden interactions. They do not confirm any specific puzzle, location, or reward.
- **Sharing a first-try success as a guide.** One success is a lead. Two or more successes with the same setup, recorded with the template above, is the beginning of a guide.
