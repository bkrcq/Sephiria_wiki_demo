# Sephiria Grimoire Build Notes

## What "Grimoire" means in Sephiria, from the official patch notes

"Grimoire" is a real, named part of Sephiria's combat system — not just a search phrase. The developer's patch notes document it from several angles:

- **A damage category.** Patch notes repeatedly reference **Grimoire Damage** as a stat: for example, update 1.0.31 (September 10, 2026) describes the Magic Wound effect, which increases Grimoire damage taken by 6% for 10 seconds, stacking up to 5 times.
- **A resource cost.** Artifacts interact with a **Grimoire MP Cost** — Rylie's Pocket Watch, named in update 0.12.0 (May 13, 2026), reduces it.
- **A haste stat.** Update 0.12.0 also improved the UI to show the cooldown reduction from **Grimoire Haste** under the Grimoire display, and the Academy Fountain Pen artifact scales Grimoire Damage with the player's Evasion.
- **Individual items.** Update 0.10.14 (February 2026) added one new Grimoire alongside six artifacts, so Grimoires also exist as collectible entries, not only as a stat block.
- **A boss name to not confuse with the system.** The Demonic Grimoire is a miniboss (its pattern was adjusted in update 1.0.33), not a piece of equipment.

What is still missing from official sources is a complete Grimoire list with per-entry effects. That is why this page pairs the confirmed mechanics above with the build-planning method below, instead of publishing a ranked list of Grimoire entries it cannot verify.

## Start with the run goal, not with an item

Every build decision gets easier once the run has a single, explicit goal. Before you pick anything, write down which of these the run is for:

- **Learning:** you are trying to understand one weapon branch, one room type, or one mechanic. Success means you learned something, not that you cleared the tower.
- **Chapter progression:** you want to reach a new chapter or finish the current one. Success means progress, so consistency matters more than peak damage.
- **Boss practice:** you want repeated attempts against one encounter. Success means more attempts per hour and cleaner reads, not a perfect kill.
- **Co-op:** you are playing with up to four players online. Success means the party finishes together, so coordination matters as much as individual damage.
- **Hard Mode:** you are working through Hard Mode's challenge structure (the 1.0 announcement lists 18 Hard Mode elements). Success means surviving long enough to learn the later stages, so durability and recovery deserve as much attention as offense.

A build that is excellent for learning can be mediocre for Hard Mode, and a build that clears chapters comfortably can fall apart in co-op if nobody covers recovery. If a guide recommends a build without naming the run goal, treat that recommendation as incomplete.

## The five questions that decide a build

Use these five questions in order. Answer them from what you have actually observed in your own runs, not from a tier list.

1. **What is my run goal?** Pick one goal from the list above. If you catch yourself chasing two goals at once, split them into two runs.
2. **Which weapon branch fits how I actually play?** Sephiria has six weapon branches and more than 200 upgrades. Choose the branch whose range, speed, and damage style you can execute consistently. A branch you control well beats a theoretically stronger branch you keep misusing.
3. **What do my artifacts and tablets actually do in this run?** Describe each pickup in one sentence based on what you saw it do, not what you assume it should do. If you cannot describe an effect from observation, mark it unknown and keep testing.
4. **What animal synergies showed up?** Animal synergies are part of the confirmed build system. Record which synergies appeared alongside which weapon and artifact choices, so you can tell later whether a strong run came from one item or from a combination.
5. **What ended the run?** Write down the cause of death or the reason you stopped: a specific room, a specific encounter, running out of recovery, or a mistake you can name. The answer to this question decides what to change next.

If you answer all five after every run, your build notes become a real experiment log instead of a pile of disconnected impressions.

## A build-planning worksheet you can reuse

Copy this template into your own notes before each run, and fill it in as you play:

- **Run goal:** one goal from the list above.
- **Weapon branch:** the branch you will use, plus the reason you chose it in one sentence.
- **Artifacts found:** each artifact, with one observed effect per item.
- **Tablets found:** each tablet, with one observed effect per item.
- **Animal synergies observed:** which synergies appeared, and with what combination.
- **Mode and party:** solo or co-op, player count, and chapter.
- **Game version:** the version shown in-game, so old notes do not get mixed with new patches.
- **What ended the run:** the specific cause, in one sentence.
- **One change for next run:** exactly one change, not five.

The last line is the most important. Changing one variable at a time is the only way to know which change helped. If you swap the weapon branch, three artifacts, and your play style in the same run, a better result tells you nothing about which change caused it.

## Reading a build result honestly

A single good run does not prove a build is strong, and a single bad run does not prove it is weak. Runs vary because of random discoveries, room layouts, and execution on the day. Before you call a build reliable, look for these signals:

- **Repeatability:** the build performs similarly across at least three runs with the same goal, not just once.
- **A known failure mode:** you can name the situation where the build struggles, such as a specific encounter type or a long stretch without recovery.
- **A recorded cause:** your notes show what ended each run, so you are comparing evidence instead of remembering only the best run.
- **Version context:** the notes say which game version they were recorded on, because balance patches can change what works.

If a build has none of these signals, it is a promising lead, not a recommendation. Say so in your notes. That honesty is what separates a useful guide from a confident guess.

## Solo, co-op, and Hard Mode need different plans

**Solo runs** reward self-sufficiency. Your plan should cover damage, recovery, and escape in one loadout, because nobody else can cover a gap. When a solo run ends, the most useful note is usually which gap appeared first.

**Co-op runs** support up to four players online, and the developer's 1.0 announcement describes teammates trading items and reviving fallen companions. That changes planning: the party can split responsibilities instead of every player building the same way. Before a co-op session, agree on who is testing what, who carries recovery, and how you will record the run. A co-op build that looks weak on paper can be the right choice if it lets the party survive longer together. See the [co-op guide](/coop) for the confirmed scope and the details that still need a primary source.

**Hard Mode** adds a separate challenge structure on top of the six chapters. Treat it as an endurance problem, not a damage race. Plans that chase maximum damage in the first floors often run out of recovery later. Record which floor a run reached, what ended it, and whether the limiting factor was damage, survival, or a mistake. Comparing Hard Mode notes across runs is more informative than comparing any two individual builds.

## Common mistakes that make builds look better than they are

- **Judging from one run.** A lucky sequence of discoveries can make any branch look unbeatable. Wait for repeatability before recommending anything.
- **Changing everything at once.** If five things change between runs, you cannot credit any one of them for the result.
- **Copying an unverified tier list.** Rankings without a stated game version, test method, and run goal are opinions, not data. The site does not publish a Grimoire tier list for exactly this reason: the supporting data is not established.
- **Ignoring the game version.** A build recorded before a patch may not behave the same way after it. Always record the version.
- **Confusing an item's existence with its strength.** The confirmed totals — 300 artifacts, 70 tablets, 200+ upgrades — describe the size of the system, not which entries are strongest. A large system makes careful testing more important, not less.
- **Forgetting the run goal.** A build that clears chapters is not automatically good for boss practice, and a boss-practice build is not automatically good for Hard Mode.

## When a build is ready to share

A build note is ready to share with other players when it contains: the run goal, the weapon branch, the artifacts and tablets used, the animal synergies observed, the mode and party size, the game version, at least three runs of evidence, and a named failure mode. Anything shorter is a draft. Drafts are fine for personal notes, but they should not be presented as recommendations.

If you later find evidence that contradicts an earlier note — a patch change, a repeated counter-example, or an official announcement — update the note and its date instead of deleting the history. Corrections with dates are how a wiki earns trust.

## Frequently asked questions

### What is the Sephiria Grimoire?

Official patch notes document Grimoire as a combat system with its own damage type (Grimoire Damage), an MP cost, and a Haste stat, plus individual Grimoire items added in updates such as 0.10.14. A complete catalogue of Grimoire entries has not been published officially, so this page documents the confirmed mechanics and treats "Grimoire build" as build planning across weapons, artifacts, tablets, and the Grimoire stats they modify.

### Can I find a confirmed Sephiria Grimoire build?

No universal Grimoire build is confirmed. Use the worksheet above, record your weapon branch, artifacts, tablets, run conditions, and game version, and judge a build by repeatability instead of by one good run.

### Are Grimoire item effects confirmed?

Specific names, effects, rarity, acquisition routes, and upgrade rules remain unconfirmed in the current sources. This page deliberately does not invent them.

### How many runs should I test before trusting a build?

At least three runs with the same goal, recorded with the same template, is a reasonable minimum. Fewer runs can suggest a lead, but they do not establish reliability.

### Should I use a different build for co-op?

Usually, yes. In co-op, the party can split responsibilities — for example, one player prioritizing recovery while others prioritize damage — because teammates can trade items and revive fallen companions, as described in the developer's 1.0 announcement. Plan the party, not just your own loadout.

### What should I change after a failed run?

Change exactly one thing: the weapon branch, one artifact choice, your positioning habit, or your run goal. Then record whether the next run actually improved, and what ended it.
